# 4. Бэкенд: модули, API, база данных, алгоритмы

Бэкенд — приложение на FastAPI в папке `backend/app`. Все эндпоинты начинаются с `/api/v1`. В режиме разработки интерактивная документация открыта на `http://localhost:8000/api/docs`. На проде она выключена из соображений безопасности.

## 4.1. Запуск приложения (`main.py`)

При старте сервера:
1. Создаётся приложение FastAPI. Подключаются CORS (запросы разрешены только с адресов сайта) и middleware с заголовками безопасности.
2. Подключаются 10 роутеров.
3. Запускается фоновый поток-планировщик: раз в 60 минут он вызывает сбор вакансий. У каждого источника свой минимальный интервал, от 2 до 6 часов.

Перед стартом Docker-контейнер выполняет:
- `alembic upgrade head` — применяет миграции базы;
- `python -m app.seed` — создаёт тарифы, администратора, базу знаний, демо и тестовых пользователей. Скрипт идемпотентный: повторный запуск ничего не дублирует.

## 4.4. Сбор вакансий (`ingest/`)

**Откуда:** 59 источников, только открытые API и страницы, где сбор разрешён.

| Тип | Сколько | Как |
|---|---|---|
| Greenhouse | 28 компаний (Airbnb, Stripe, Figma, Discord, Robinhood, Coinbase…) | Официальный публичный API карьерных страниц |
| Ashby | 8 (Ramp, Notion, OpenAI, Linear…) | Публичный API |
| Lever | 3 (Spotify, Palantir, Zoox) | Публичный API |
| Remotive, RemoteOK, Himalayas, Jobicy | 4 | Открытые API досок удалённой работы, только вакансии, доступные из США |
| Talent.com | несколько запросов «должность + город» | HTML-страница `/jobs`, сбор которой разрешён в robots.txt |
| Telegram | каналы с вакансиями | Публичный веб-просмотр `t.me/s/канал` |
| Adzuna, USAJOBS | 2 | Готовы, включатся, когда будут API-ключи |

**Почему не Indeed, LinkedIn, ZipRecruiter, Monster, SimplyHired, Wellfound.** Эти сайты защищены от ботов (отвечают 403), а LinkedIn прямо запрещает сбор данных. Поэтому они показаны ссылками *Search on other boards* с готовым поиском, а не собираются.

**Обработка каждой вакансии (`parse.py`):**
1. Чистим HTML, исправляем сломанную кодировку (у RemoteOK встречались «кракозябры») и HTML-сущности.
2. Фильтруем по локации: оставляем только США и удалёнку из США (по штатам, городам и ключевым словам).
3. Разбираем зарплату из текста (`$120K–$150K`, `$28.50/hr`, `90,000 per year`), определяем период (час, неделя, месяц, год) и пересчитываем в годовую сумму. Нереалистичные значения отбрасываем: в год меньше $8k или больше $1.5M.
4. Определяем уровень (intern … executive) и категорию по заголовку.
5. Считаем отпечаток (`fingerprint`) из должности, компании и города. Одна и та же вакансия с разных сайтов помечается дублем.

**Актуальность (`runner.py`):**
- для источников с полным списком (Greenhouse, Lever и т. д.) вакансия, пропавшая из ответа, сразу деактивируется;
- для остальных вакансия гаснет, если её не видели 7 дней.

Каждый запуск пишется в `ingestion_runs`: сколько найдено, создано и обновлено, ошибки. Администратор видит это на странице Job sources.

## 4.5. ИИ (`ai/`)

**Две модели — дешёвая и умная** (`provider.py`, словарь `TASK_TIER`):

| Задача | Модель | Почему |
|---|---|---|
| Разбор резюме, объяснение зарплаты | `gpt-5.4-mini` (быстрая) | Простая работа, важна скорость и цена |
| ATS-анализ, генерация резюме, сопроводительное, переговоры | `gpt-5.5` (умная) | Важно качество |
| Ассистент | авто | Короткий простой вопрос идёт в быструю модель. Длинный (больше 400 символов) или сложный (подготовка к интервью, стратегия, переговоры) — в умную |

Так ответы на обычные вопросы стоят в разы дешевле, а для сложных задач используется полноценная модель.

**Строгие ответы.** Для всех задач, кроме ассистента, модель возвращает JSON строго по схеме Pydantic (Structured Outputs). Ответ в другом формате невозможен.

**Учёт.** Каждый вызов (задача, модель, токены, время, статус) пишется в `ai_calls` в фоновом потоке, чтобы не замедлять ответ. Текст запросов и ответов там не хранится.

**Без ключа** всё работает на правилах: эвристический разбор резюме, сопоставление ключевых слов, ассистент на шаблонах по данным пользователя.

**Защита от выдуманных фактов в резюме (`resume/analysis.validate`).** После генерации результат сравнивается с подтверждёнными данными:
- новые работодатели, должности, учебные заведения;
- цифры, которых не было в исходнике (например, «увеличил выручку на 300%»).

Если что-то найдено, версия ИИ не сохраняется, а используется безопасная версия, собранная по правилам из исходных данных. Пользователь видит проверку *Unsupported Claims*.

**Защита от промпт-инъекций** описана в разделе 6.

## 4.6. Зарплаты (`salary.py`)

**Market research:**
1. Ищем активные вакансии с зарплатой по словам из должности. Сначала в городе (с учётом штата), затем расширяем поиск: без уровня, затем без города, пока не наберётся хотя бы 5 вакансий.
2. Для каждой берём середину вилки и пересчитываем в годовую сумму.
3. Если вакансий 8 и больше, отбрасываем выбросы вне диапазона 0.35–3 медианы (ошибки распознавания).
4. Считаем минимум, 25-й процентиль, медиану, среднее, 75-й процентиль, максимум и медианы по уровням. Добавляем топ компаний, источники, период наблюдения и ограничения данных.

**Личная оценка (assess):**
1. Берём статистику рынка по желаемой или текущей должности и городу.
2. Точка на шкале зависит от уровня: entry — 25-й процентиль, mid — медиана, senior — 70-й и т. д. Уровень вычисляется из лет опыта.
3. Надбавка за навыки: сравниваем медиану вакансий, где навык упоминается, с общей медианой. Учитываем максимум 3 навыка и ограничиваем вклад. Магистратура или PhD дают +3%.
4. Диапазон строится вокруг точки по межквартильному размаху.
5. Уверенность: high — от 40 вакансий в конкретном городе, medium — от 12, иначе low. Список *missing information* показывает, что добавить в профиль для точности.

## 4.7. Тарифы и лимиты (`entitlements.py`)

- Тарифы и лимиты лежат в таблице `plans`, и админ их меняет. `-1` означает «без лимита», `0` — «не входит в тариф».
- Перед платным действием вызывается `check(db, user, feature)`:
  - если функция не входит в план, возвращается код 402 и `feature_not_included`;
  - если лимит исчерпан — 402 и `limit_reached`.

  Фронт по коду 402 показывает плашку апгрейда.
- После успешного действия вызывается `consume()`, который увеличивает счётчик в `usage_records` за текущий месяц (`YYYY-MM`). С новым месяцем начинается новый счётчик, поэтому лимиты обнуляются сами.
- Подписка в тестовом режиме продлевается автоматически при истечении. Подписка Stripe продлевается только событием от Stripe; если оно не пришло, даётся 3 дня отсрочки.

## 4.8. Аудит и уведомления (`services.py`)

- `audit(...)` записывает действие в `audit_logs`: кто, что, над чем, IP, детали. Пишутся входы, выходы, смены пароля, подписки, отмены, все действия администратора, экспорты, удаление аккаунта.
- `notify(...)` создаёт уведомление для колокольчика.
- `send_email(...)` отправляет через SMTP. Без SMTP пишет в лог, а ссылка подтверждения возвращается на экран (демо-режим).
