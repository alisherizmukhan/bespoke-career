# 7. Оплата и маркетинговая модель

## 7.1. Как устроена оплата

Оплата работает в одном из двух режимов. Режим выбирается автоматически по наличию ключа.

| Режим | Когда | Что происходит |
|---|---|---|
| **Встроенный тестовый** | Переменная `STRIPE_SECRET_KEY` не задана (так сейчас на проде) | Подписка и тестовый платёж записываются в базу, деньги не списываются. Сверху жёлтая плашка *Test mode* |
| **Stripe** | Задан ключ `sk_test_…` (тестовый режим Stripe) или `sk_live_…` (реальные деньги) | Настоящая страница оплаты Stripe Checkout, списание с карты, автопродление, вебхуки |

Код Stripe написан на чистом REST API через `httpx`, без SDK: меньше зависимостей. Версия API Stripe закреплена (`2024-06-20`), чтобы формат ответов не менялся неожиданно. Файл `backend/app/payments.py`.

### Путь покупки через Stripe
1. Пользователь нажимает **Confirm and pay**. Фронт вызывает `POST /billing/checkout`.
2. Бэкенд создаёт в Stripe продукт `bespoke_pro` (один раз, у продукта фиксированный id) и **Checkout Session** с режимом `subscription`, ценой из нашей таблицы `plans` и периодом month или year. В сессию записываются id пользователя, план и период.
3. Бэкенд возвращает `checkout_url`, и браузер уходит на страницу Stripe. **Номер карты вводится на сайте Stripe, а не у нас**, поэтому данные карт к нам вообще не попадают (требования PCI DSS выполняет Stripe).
4. После оплаты Stripe возвращает на `/app/billing?checkout=success&session_id=cs_…`.
5. Фронт вызывает `POST /billing/checkout/confirm`. Бэкенд запрашивает сессию у Stripe, проверяет, что она принадлежит этому пользователю и оплачена, создаёт подписку и записывает платёж.
6. Параллельно Stripe присылает вебхук `checkout.session.completed`. Обработка **идемпотентна**: подписка ищется по id в Stripe, платёж — по id счёта. Второй раз ничего не создаётся, двойного списания в учёте нет.

### Продление, смена плана, отмена
| Событие | Как обрабатывается |
|---|---|
| Продление (новый месяц или год) | Stripe списывает сам и шлёт вебхук `invoice.paid`. Мы продлеваем период и пишем платёж |
| Неудачное списание | `invoice.payment_failed` переводит подписку в статус `past_due`. Доступ сохраняется ещё 3 дня |
| Смена плана или периода | `POST /billing/change-plan` обновляет подписку в Stripe. Разница доплачивается сразу (proration, `always_invoice`) |
| Отмена | `POST /billing/cancel` ставит в Stripe `cancel_at_period_end=true`, и доступ остаётся до конца оплаченного периода |
| Возобновление | `POST /billing/resume` снимает отмену |
| Подписка закончилась | `customer.subscription.deleted` → статус `canceled`, пользователь на Free |
| Карта и счета | `POST /billing/portal` возвращает ссылку на портал клиента Stripe |
| Удаление аккаунта | Подписка в Stripe отменяется сразу |

### Как включить настоящую оплату
1. Зарегистрироваться на stripe.com (бесплатно) и в режиме Test взять ключ `sk_test_…`.
2. В Railway → `bespoke-api` → Variables добавить `STRIPE_SECRET_KEY`.
3. Зарегистрировать вебхук. Команда напечатает `STRIPE_WEBHOOK_SECRET=whsec_…`, его нужно добавить в Railway:
   ```
   STRIPE_SECRET_KEY=sk_test_... python -m app.stripe_setup https://bespoke-api-production-6091256b.up.railway.app/api/v1/billing/webhooks/stripe
   ```
4. Для реальных денег сделать то же самое с ключом `sk_live_…` после активации аккаунта Stripe. Плашка тестового режима исчезнет сама.

Тестовые карты Stripe: `4242 4242 4242 4242` — успешная оплата, `4000 0000 0000 9995` — отказ. Дата — любая будущая, CVC — любой.

## 7.2. Тарифная модель

| | Free | Career Plus | **Career Pro** | Career Family |
|---|---|---|---|---|
| Помесячно | $0 | $19 | $39 | $59 |
| За год | — | $144 | $288 | $444 |
| В месяц при годовой оплате | — | $12 | $24 | $37 |
| Экономия за год | — | $84 (37%) | $180 (38%) | $264 (37%) |

Почему именно так:
- **Free** даёт попробовать каждую функцию в малом объёме (3 резюме, 5 откликов, 1 оценка). Пользователь доходит до лимита в момент, когда уже видит ценность.
- **Pro** — целевой план: в нём уникальная функция (помощник по переговорам) и «безлимит» на ключевые действия.
- **Family** дороже Pro и служит якорем: на его фоне Pro выглядит разумной ценой (эффект приманки).
- **Годовая скидка около 37%** вместо типичных 17% («2 месяца бесплатно»). Годовой клиент приносит деньги вперёд и реже уходит, потому что ищет работу несколько месяцев.

## 7.3. Маркетинговые приёмы на сайте

Приёмы взяты из исследований поведенческой экономики и практики SaaS: якорение, эффект приманки, переформулирование цены, рекомендованный план. Сознательно **не использованы** манипуляции, за которые штрафует FTC (Федеральная торговая комиссия США): фальшивые таймеры, «осталось 2 места», выдуманные отзывы и счётчики клиентов, спрятанная кнопка отмены.

## 7.4. Аналитика для бизнеса (CRM)
В админке считаются MRR (ежемесячная повторяющаяся выручка; годовые подписки делятся на 12), ARR, ARPU (средний чек), конверсия из бесплатных в платящих, доля годовых подписок, выручка за всё время по каждому клиенту и этапы жизненного цикла. Всё выгружается в Excel.
