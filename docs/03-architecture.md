# 3. Архитектура и технологии

## Общая схема

```
             Браузер пользователя
                     │  HTTPS
     ┌───────────────┴────────────────┐
     ▼                                ▼
 Vercel (фронтенд)               Railway (бэкенд)
 Next.js 15 / React 19   ──JSON──▶ FastAPI (Python 3.12, Docker)
 страницы, интерфейс               REST API /api/v1/*
                                       │
              ┌────────────────────────┼──────────────────────────┐
              ▼                        ▼                          ▼
      Railway PostgreSQL 18       OpenAI API                 Stripe API
      (все данные)                (ИИ: резюме, ассистент)    (оплата)
                                       ▲
                                       │ раз в час
              Планировщик сбора вакансий (внутри бэкенда)
              ← Greenhouse, Lever, Ashby, Remotive, RemoteOK,
                Himalayas, Jobicy, Talent.com, Telegram

 Railway не усыпляет сервис: планировщик работает постоянно
```

Система разделена на две независимые части, которые общаются только через JSON API:
- **Фронтенд** отвечает только за интерфейс. Секретов и бизнес-логики в нём нет.
- **Бэкенд** отвечает за данные, правила, лимиты, ИИ, оплату и сбор вакансий.

Такое разделение позволяет хостить части на разных платформах, а в будущем подключить мобильное приложение к тому же API.

## Технологии и почему выбраны именно они

### Бэкенд
| Технология | Зачем | Почему она |
|---|---|---|
| **Python 3.12** | Язык бэкенда | Лучшие библиотеки для ИИ, парсинга PDF и DOCX, обработки текста |
| **FastAPI** | Веб-фреймворк, REST API | Быстрый, асинхронный, сам проверяет входные данные через Pydantic и сам генерирует документацию API |
| **Pydantic v2** | Схемы и валидация данных | Каждый запрос проверяется по схеме: неверные данные отклоняются с понятной ошибкой ещё до логики |
| **SQLAlchemy 2** | ORM для работы с БД | Запросы параметризованы, что защищает от SQL-инъекций. Один код работает и с PostgreSQL, и с SQLite |
| **Alembic** | Миграции схемы БД | Версионирование структуры базы: 4 миграции применяются автоматически при каждом деплое |
| **PostgreSQL 18** | Основная база (прод) | Надёжная реляционная база, управляемый сервис Railway |
| **SQLite** | База для разработки и тестов | Не нужен отдельный сервер. Тесты каждый раз работают на чистой базе |
| **bcrypt** | Хэширование паролей | Стандарт индустрии, медленный хэш с солью |
| **PyJWT** | Токены сессий | Подписанные токены без хранения сессий на сервере |
| **httpx** | HTTP-клиент | Запросы к источникам вакансий и Stripe API |
| **BeautifulSoup + lxml** | Разбор HTML | Сбор вакансий с Talent.com и Telegram, очистка HTML в описаниях |
| **pypdf, python-docx** | Чтение резюме | Извлечение текста из загруженных PDF и DOCX |
| **fpdf2, python-docx** | Генерация резюме | Экспорт резюме в PDF и DOCX в трёх шаблонах |
| **openpyxl** | Excel | Экспорт таблиц админки в .xlsx |
| **openai SDK** | ИИ | Вызовы моделей GPT со строго типизированным ответом |
| **pytest** | Тесты | 35 автотестов |
| **Docker** | Упаковка бэкенда | Одинаковая среда локально и на Railway |

### Фронтенд
| Технология | Зачем | Почему она |
|---|---|---|
| **Next.js 15.5** (App Router) | Фреймворк | Маршрутизация по папкам, быстрая загрузка, удобный деплой на Vercel. Версия 15.5.29 выбрана потому, что Vercel заблокировал уязвимую 15.1 |
| **React 19** | UI-библиотека | Компонентный подход |
| **TypeScript** | Язык | Типы ловят ошибки до запуска. Перед каждым деплоем запускается проверка `tsc` |
| **Tailwind CSS 3** | Стили | Дизайн-токены (цвета, шрифты, радиусы) в одном конфиге, стили рядом с разметкой |
| **TanStack Query** | Работа с API | Кэширование, повторные запросы, состояния загрузки и ошибок |
| **React Hook Form + Zod** | Формы | Валидация форм на клиенте с понятными ошибками |
| **Phosphor Icons** | Иконки | Единый набор иконок с характером вместо «типичных ИИ-иконок» (раздел 8) |
| **@fontsource** (Instrument Sans, IBM Plex Mono) | Шрифты | Шрифты лежат вместе с сайтом, а не грузятся с Google, поэтому сборка не зависит от внешних сервисов |

### Внешние сервисы
| Сервис | Роль | Тариф |
|---|---|---|
| **Vercel** | Хостинг фронтенда, CDN, HTTPS | Бесплатный |
| **Railway** | Хостинг бэкенда (Docker из репозитория) и PostgreSQL | Пробный период, затем оплата по использованию |
| **GitHub** | Код, источник автодеплоя Railway | Бесплатный |
| **OpenAI** | Модели ИИ: `gpt-5.4-mini` (быстрая) и `gpt-5.5` (умная) | Оплата за использование |
| **Stripe** | Приём платежей, подписки | Комиссия с платежа (тестовый режим бесплатен) |

## Как проходит один запрос (пример: «сгенерировать резюме»)

1. Пользователь нажимает **Generate version**. Компонент вызывает `api("/resume-intelligence/generate", {body: …})` из `lib/api.ts`.
2. `api.ts` добавляет заголовок `Authorization: Bearer <токен>` и отправляет запрос на API в Railway.
3. FastAPI находит обработчик `generate` в `routers/resumes.py`. Pydantic проверяет тело запроса по схеме `GenerateIn`.
4. `get_current_user` (из `security.py`) проверяет подпись и срок токена, статус аккаунта и не отозвана ли сессия.
5. `rate_limit` проверяет, что запросов не больше 15 в минуту.
6. `entitlements.check` проверяет, что лимит генераций по тарифу не исчерпан. Если исчерпан, возвращается код 402 и фронт показывает плашку апгрейда.
7. Проверяется, что резюме принадлежит этому пользователю.
8. `resume/analysis.generate` отправляет в OpenAI подтверждённые данные и текст вакансии, обёрнутые в теги-ограждения. Ответ приходит строго по схеме `GeneratedResume`.
9. `validate` сравнивает результат с исходными данными. Новые компании, должности и цифры считаются выдумкой: такая версия отклоняется, и используется безопасная версия без ИИ.
10. Версия сохраняется, использование списывается, событие пишется в аудит. Фронт получает JSON и показывает новую версию.

## Режимы работы без внешних сервисов

Сервис спроектирован так, чтобы работать даже без внешних ключей:

| Нет… | Что происходит |
|---|---|
| Ключа OpenAI | Разбор резюме, анализ и ассистент работают на правилах (эвристиках) |
| Ключа Stripe | Встроенный тестовый режим оплаты: подписка оформляется без списания |
| SMTP (почты) | Ссылка подтверждения показывается прямо на экране (демо-режим) |
| S3 | Файлы хранятся на диске сервера |

Поэтому проект можно запустить локально одной командой и показать целиком.
